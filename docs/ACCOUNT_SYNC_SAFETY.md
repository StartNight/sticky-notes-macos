# 微软账号切换与凭据边界

## 数据归属

- 每张便笺新增可选 `ownerAccountID`，取自已确认的 Graph `/me.id`，不使用邮箱地址猜账号。
- 新登录在取得 `/me.id` 前不得同步；已保存的新会话身份与令牌存于同一个会话 blob。
- 拉取匹配、上传、删除墓碑、内存删除队列均限定账号；同名 remoteId 不跨账号匹配。
- 每次操作捕获账号和登录代次 UUID。所有 HTTP 请求前、响应后、刷新重试前后检查；退出/重登使旧操作失效。
- 原数据库就地轻量迁移，绝不清库。旧便笺缺归属时全部保留，连同 remoteId/changeKey/webNoteJSON 留在本地隔离，不猜归属、不向新账号发送。重新拉取可能多出一份有归属的云端副本，这是保全旧修改的有意取舍。
- 登录且身份有效时新建的便笺归当前账号；明确未登录时新建的便笺标记为无账号纯本地（`__local_unlinked__`）；身份未确认或登录中（`.blocked`）时禁止新建，避免生成归属不明的孤儿便笺。
- 首次登录采纳及「设置 → 本地数据」中的接纳操作仅接纳无账号纯本地便笺（`__local_unlinked__`）；遗留无归属便笺（`ownerAccountID == nil`）统一隔离在「本地数据 → 隔离区」，其中无云端痕迹且未删除的条目可单条认领，含云端痕迹或已标记删除的条目仅允许显式复制为当前账号的新便笺或导出，绝不自动归属或静默合并。
- 列表、搜索与窗口显示严格限定在当前激活的账号作用域（`ActiveScope`）内；其他账号、无账号（已登录时）及隔离区便笺在主列表中隐藏并仅给出管理入口提示。本地文件仍由同一 macOS 用户持有，这是账号同步与视图隔离，不是操作系统级多用户加密。
- 最后同步时间按账号存储。当前实现没有持久化 delta 游标或真实文件夹 ID；不能把以后新增的这类元数据做成全局字段。
- 全新非沙盒安装使用应用专属目录 `~/Library/Application Support/com.shenanigans.sticky-notes/default.store`（已有旧容器库或根目录库沿用原路径，并在首次打开前做只读副本备份，含正确命名的 SQLite `-wal`/`-shm` 与外部存储目录）。若读取历史容器库遇 macOS TCC 拒权（`EPERM`/`EACCES`）或数据库打开失败，停止启动并弹出严重错误提示保留原库，绝不静默新建分裂库或删库重建。

## 认证与钥匙串

- 直接使用 `ASWebAuthenticationSession`，没有 MSAL，也没有自行启动外部浏览器。系统可能以浏览器 UI 承载该会话。
- 每次交互登录均带 `prompt=select_account`，请求 ephemeral 会话，避免借用已有浏览器 cookies；OAuth 与 `/me` 请求默认使用专用 `URLSessionConfiguration.ephemeral`（无磁盘缓存、无持久 Cookie）。代价是失去浏览器 SSO/记住账号的便利，可能要求重新输入账号及 MFA；系统浏览器或企业策略是否完全遵从必须实测。
- 显式退出先失效代次、取消 OAuth/身份/恢复/刷新任务、清空进程内缓存与内存钥匙串缓存（递增 `epoch`），再在后台准确删除统一会话项 `ms_auth_session`（受 `requiredEpoch` 保护，避免晚到的登出任务误删随后新登录的会话）。旧版五个按字段拆分的条目不由退出自动删除，仅可在「设置 → 本地数据」中经二次确认手动清理。不触及其他 service、不改 ACL、不删除 token 文件。
- 退出标记保证清理失败时也不会重开自动恢复。HTTP 刷新拒绝（400/401）只使当前会话失效并清空进程内令牌缓存，不自动删除用户现有钥匙串凭据。
- 移除自动读取开发 token 文件的代码，避免退出后重新播种旧账号；文件原件不动。
- 钥匙串读取受锁保护，成功、缺失、拒绝均在进程内记忆。拒绝不再换后端重试并自动覆盖。
- 启动恢复先以非交互模式（`kSecUseAuthenticationUIFail`）探测登录钥匙串，命中统一会话后不再自动重写；若系统要求交互授权，则先弹出应用内说明，用户同意后本次启动最多执行一次交互读取，拒绝或取消不改动任何钥匙串项或便笺。
- 新登录整包替换统一会话，刷新整包更新令牌（采用先准备、再写入、成功后提交缓存的原子顺序，并在 `errSecDuplicateItem` 时自动回退更新）；刷新及身份查询各 single-flight 且具备防系统时钟回拨保护。旧多字段发现限已知五个字段，迁移后不自动删除原件。
- 钥匙串保存失败会反馈；显式退出删除失败会提示。不能保证任意签名/ACL 状态下零系统弹窗。

## 安全测量（不记录任何值）

`AUTH_FLOW phase=restore/login/refresh/logout` 为阶段边界。`AUTH_KEYCHAIN` 只记录操作、后端、OSStatus 和累计逻辑读/写/删除次数；`sec=update/add` 补充写入底层调用。不得添加令牌、正文、账号 ID/邮箱、授权完整 URL、请求头或请求体日志。逻辑写一次可能是 Update + Add，不能将调用次数等同于弹窗次数。

GUI 测试人员需记录：阶段、同一二进制 SHA、起止时间（Asia/Shanghai UTC+8）、手工看到的弹窗数、非敏感提示类别、上述计数差值和状态码。不代点允许/始终允许，不扩大 ACL。

1. 新签名包首次启动：独立 macOS 测试用户，先核对目标二进制；登录前后分别计数。
2. 已登录冷启动：退出整个进程后重开同一包，记录 restore 的读取与是否写入；统一会话命中不应自动重写。
3. 点击登录：观察能否输入另一账号/选择账号，记录 token 和 profile 两次逻辑会话保存；不能用浏览器账号列表是否为空判定失败。
4. 刷新：仅测试账号自然过期后触发同步，或经批准的隔离测试工具；不要改用户实际 token/到期字段。记录一次刷新网络请求和一次逻辑写，多个调用应合并。若未出现 AUTH_FLOW refresh，则该阶段未测。
5. 显式退出及重开：只在测试用户的测试凭据上执行，记录 logout 删除状态；重开应保持未登录，不读取开发 token 文件。不能为了验证而退出当前真实会话。
6. A→B→A：各自建立不同的 QA 便笺（需用户另行授权真实 Graph 写入），在 A 有待上传修改/删除/防抖时切 B；B 不收到 A 的正文、remoteId、JSON，A 的墓碑不得删除 B；回 A 才恢复 A 的同步。另测相同 remoteId 的 mock 碰撞、旧无归属便笺、离线本地便笺的显式接纳。

## 证据等级

自动测试使用独立临时 SwiftData 库、内存钥匙串后端和 MockURLProtocol。通过不等于真实微软网页登录、系统钥匙串弹窗或端到端同步通过。正式放行仍需 GUI 和两个测试账号验收；不得因单测通过关闭 P1。


## 1446fc2 独立 QA 五项复核后的生命周期加固

以下均先由源码确认风险，不是对真实用户库/微软账号的动态复现。修复用可控网络屏障、独立临时库和 mock 身份验证。

1. **error 也可能包含未上传修改**：拉取遇远端新版本，对 pendingUpload 和 error 均走冲突保全；副本保留文字、富文本、颜色、音频及原始 JSON。不能把错误状态当作干净副本覆盖。
2. **同进程写入串行化与响应版本**：全量同步抑制重入；同一 SyncEngine 的单便笺上传用 FIFO 异步互斥，递归刷新在锁内执行；全量/防抖共用同一入口。响应按发出时内容快照核对，变更后的正文/颜色/富文本/音频不能因旧响应提前 synced。缓存颜色记录实际发出的值；已知新 remoteId/changeKey 仍保存，新修改保留 pendingUpload。所有待处理改动/墓碑/清理/未确认创建完成前，不更新整体成功时间。这不是跨进程锁，也不是服务端事务或全局冲突序列化。
3. **POST 不确定结果采用持久化安全阻塞，不承诺 exactly-once**：每次 POST 前保存 pendingCreateOperationID、非敏感 endpoint 路径与开始时间，账号归属保存在同一便笺。保存失败不发请求。client-request-id 仅用于关联诊断，微软未承诺其为幂等键。只有明确拒绝响应（4xx）或确定尚未发出字节的发送前网络错误（断网、DNS 失败、连接被拒等 `URLError`）可释放该意图以继续重试/fallback；超时、连接中断、5xx、成功但缺可用对象、退出/切号后丢响应等均保留意图。回原账号或重开后不能自动再次 POST，也不通过文本相似度猜测云端对象关联。界面提示待核对、内容保留；相关创建、替换、删除保持错误/待确认，不伪报成功。

   这只能防止程序盲目再创建，不能撤销已到服务器的 POST，不能保证没有孤立云端对象，也不能自动认领同内容云端副本。一次 POST 可能已落地，新拉取可能看到独立云端副本；原本地来源不被自动合并/删掉。6a982c4 当时尚无解除 UI；本轮在下节补受支持的原账号人工辅助恢复，仍不建议手改数据库、仅清标记重试或自动删除疑似副本。 特别是本地已删除且创建结果未知时，仍持久保留墓碑和内容作为恢复证据，不自动丢行。
4. **删除与防抖**：两个删除 UI 都通过统一入口 `SyncEngine.requestDeletion` 先调用 `prepareForDeletion`，取消待执行防抖并保存墓碑，再核查是否存在未确认新建/恢复暂停/待核对删除/损坏日志，安全时才发起远端 DELETE 并在成功后清理本地墓碑（保留纯审计历史的墓碑转入 `recoveryPaused + .synced`，不阻塞后续同步）。上传入口及 fallback 重建入口检查墓碑；在途 PATCH 404 不得重建。已接受 POST 若成功响应仍可在同代次取得，保存 remoteId 与墓碑，后续 DELETE 清理；若结果未知则按第3条阻塞。取消请求本身不代表服务器撤销。
5. **删除失败与旧对象清理**：拉取只跳过已知墓碑/retired ID（含 `recoveryPendingDeleteID`），不吞删除失败。统一删除阶段汇总失败；本轮改为先继续无关安全上传再整体上报，失败不得 idle/更新成功时间。替换创建在写新 remoteId 时，同一持久提交保存旧 ID 清理日志 pendingCleanupRemoteIDs，成功删除后才移除该 ID；新 SyncEngine/重开仍能补删，拉取不把旧对象再插成新便笺。清理失败不把已成功上传的正文误当未上传并再次替换创建。日志解析损坏时停用自动写入/删除，对应字段 setter 拒绝覆盖损坏原始字节，确保原始数据不被静默擦除。

### 回归证据的范围

新增网络屏障显式卡住响应后再编辑/切号/删除或启动另一同步，涵盖错误状态冲突、full/debounce/上传并行、v1响应迟于v2编辑、已接受201后切号、超时后重开、删除后PATCH404、防抖取消、已接受创建后删除、未知创建墓碑、DELETE500、替换日志重启、损坏日志和未持久化便笺禁止POST。磁盘重开测试仅使用测试生成的库；旧 schema fixture 仍不是用户当前实际旧库升级证明。

原“error 下次重试”用例现在采用已知 remoteId 的可幂等 PATCH 夹具；未知 CREATE 超时不能沿用自动重试预期，另有专门断言保留意图并阻止第二次 POST。此为明确的安全行为变更，不是把未知创建重试视为通过。

真实 GUI/双账号/云端写入仍待用户批准退出旧包、正常 AX 权限、测试账号与限定 QA 数据写入清理范围；所有自动测试通过也不代表系统放行。


## 6a982c4 QA 后的最小人工辅助恢复闭环

- 设置→微软账号→待核对与恢复（含已删除便笺）：仅在当前账号身份已通过 `/me` 校验（`isIdentityVerified`）后开放，仅展示当前原 Graph accountID 下的问题/恢复历史，包括隐藏墓碑。B 不展示、不导出、不处理 A。
- 可选导出由用户点选并自行选保存位置（写出后设为 `0600` 仅当前用户可读）；JSON 包含正文、富文本、音频、原始 JSON、账号/操作/旧ID/审计，不含认证数据。损坏日志原始字节也保留；内容文件本身有隐私，不能自动外发。
- 核对只读 fresh `/me?$select=id`（401 时允许刷新一次令牌重试）+ 原账号固定端点下的精确 ID；不按文字相似、首屏列表或邮箱推断归属。邮件候选还需精确 IPM.StickyNote 分类。404 不是“未创建”证据。
- 用户填写无秘密的核对理由、勾选风险、再次确认操作。服务层重核账号/登录代次/源记录版本/未知操作ID/墓碑/远端changeKey。这里验证可访问性/对象类型，不是证明“该对象就是未知POST结果”：关联关系仍依赖用户人工证据，可认错，不能宣称零重复。
- 关联：保全本地全内容快照；已拉回的同远端ID本地副本归档、暂停且不删除其内容。含未决操作或正在上传的重复副本拒绝关联。源正文保留、恢复可见并允许后续PATCH；PATCH失败不自动POST替换或删除。恢复后远端出现并发更改，暂停并再次人工核对，绝不借冲突副本自动新建。
- 删除：只删用户明确确认且复核的精确候选/保留旧ID。先持久化授权和具体ID/类型再DELETE。失败/切号/丢响应保留日志，绝不后台盲重试。重开后原账号可再次核对同ID；已授权目标404可由用户再次确认完成本地记录。内容仍保留本地暂停。单独删旧ID不解除另一未知POST。
- 明确重建：提示旧POST可能已落地并要求用户接受重复风险；持久保全旧内容/操作/引用/审计，持有单便笺锁直接执行一次新的带持久意图POST；不能仅清标记。旧引用不自动清理；新请求未知仍保留新意图。再次创建必须重新确认，旧确认版本不能重放。
- 仅恢复本地可见：保留未知标记，暂停同步，不执行Graph。
- 防抖字典只持有尚未发送的延迟；任务开始发送前移出字典。后续输入仅合并下一延迟并排队，不取消已发CREATE。真正丢响应仍按未知保护，不把本地锁说成服务端幂等。
- 未知墓碑/DELETE失败仅隔离自身，无关安全上传继续；整体显示未完成及问题数，不更新时间戳。恢复审计快照及已完成远端清理的纯审计墓碑（`recoveryPaused + .synced`）不被当作云端待处理；未决未知操作/待删/保留旧引用/损坏日志仍计问题。

### 明确未验证
本轮所有网络/恢复操作仅 fake account + MockURLProtocol；临时内存/磁盘fixture，不开真实数据库/凭据/Keychain/运行App。GUI恢复布局和文件选择器、真实Graph资源类型/权限/返回语义、实机交错、真实旧库迁移/磁盘失败/进程崩溃、跨进程互斥、arm64运行均待验证。GET复核与DELETE之间仍有远端并发窗口；不是原子事务。恢复后邮箱对象可能无法PATCH，保持阻塞并要求明确重建。不能证明所有孤立对象已发现或删除。
